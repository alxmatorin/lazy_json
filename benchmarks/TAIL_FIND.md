# Ускорение find $key1.key2

Следующий этап: [аналогичные оптимизации обратного обхода](BACKWARD_FIND.md).

Оптимизирован прямой поиск `$key1.key2` на документе из `KeysScenario` (512 022 байта). Путь, направление обхода и содержимое сценария сохранены. «До» — версия после предыдущего раунда исправлений, на начало этой задачи.

В `ByteScanner` изменён прямой проход:

- Восемь маркеров скобок суммируются умножением вместо `Long.bitCount`. Маска содержит только байты 0 и 0x80; сумма 0..8 помещается в старший байт без переноса между счётчиками.
- Глубина и состояние строки хранятся в локальных переменных горячего цикла; поля используются для передачи состояния побайтовому разбору escape-последовательностей и хвоста.
- Длинный участок строки пропускается отдельным циклом с проверкой до 32 байт за итерацию. Для коротких строк сначала читается один 8-байтовый блок.
- Проверки границ прямого прохода записаны через `p <= length - blockSize`, без сложения позиции с размером блока.

Новых зависимостей и специальных флагов JVM нет. Jackson по-прежнему выполняет полный цикл `byte[] → Map → изменение → byte[]`.

## Результаты

macOS arm64, Temurin JDK 21.0.7, `-Xms512m -Xmx512m`. Три отдельных JVM на версию, чередование «до/после». Каждая операция: 3 окна прогрева по 200 мс и 5 окон измерения по 200 мс; ниже медиана трёх медиан. Документ создаётся до измерений. ## Проверка и повторение

79 тестов проходят. Добавлены поиск `[42]` в настоящем `KeysScenario`, 1280 комбинаций длинных строк с экранированием и скобками на границах блоков, а также сохранение первого результата при повторяющемся корневом ключе. Существующие случайные проверки обоих направлений сканирования и проверка результата замен через Jackson также проходят.

Для запуска на выбранном JDK 21:

```sh
mvn test dependency:build-classpath -Dmdep.outputFile=target/benchmark-classpath.txt
java -Xms512m -Xmx512m \
  -cp "target/test-classes:target/classes:$(cat target/benchmark-classpath.txt)" \
  ru.sber.lazyjson.KeysFindBenchmark
```

Для сравнения другой версии используйте тот же `KeysFindBenchmark` и его помощник `JsonBytesBenchmark`, одинаковые JVM и параметры памяти. Повторите команду `java` три раза в отдельных JVM.
