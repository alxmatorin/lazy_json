# Ускорение обратного обхода

В `skipContainerBack` перенесены оптимизации прямого прохода: `countMarkers` вместо `Long.bitCount`, локальные `depth`/`inString`, пропуск длинных строк отдельным циклом по 32 байта и проверки границ через минимально допустимую позицию. Поля состояния остаются для побайтового разбора escape-последовательностей и края документа.

Для выбора самого правого символа используется `exactStringHits`. Обычный `stringHits` пригоден для проверки на ноль и выбора самого левого совпадения: его маска может содержать лишние биты выше настоящего совпадения. Переносить его буквально в обратный поиск нельзя. Проверка чётности слешей перед кавычкой, в том числе на границе блока, сохранена.

## Замеры

Сравнение с состоянием после оптимизации прямого обхода. macOS arm64, Temurin JDK 21.0.7, `-Xms512m -Xmx512m`. Три JVM для каждой версии с чередованием «до/после»; в каждой операции три окна прогрева по 200 мс и пять измерений по 200 мс. Таблица — медиана трёх медиан. Это локальный сравнительный стенд, результат зависит от данных, архитектуры и JDK.

`across-document` ищет `<$key3.key4` с конца исходного `KeysScenario` размером 512 022 байта. `key5`, `key` и `filler2` — обратный поиск этих значений как больших контейнеров в отдельном корневом объекте. `long-string` — строка на 500 000 байт. `short-tail` — исходный быстрый хинт `<$key1.key2`; `forward/control` контролирует прямой проход.

| Операция | До, мкс | После, мкс | Ускорение | Байты/операцию до → после |
|---|---:|---:|---:|---:|
| `backward/short-tail` | 0.073 | 0.074 | 0.99× | 96 → 96 |
| `backward/across-document` | 113.024 | 103.102 | 1.10× | 96 → 96 |
| `forward/control` | 81.689 | 82.403 | 0.99× | 96 → 96 |
| `backward/key5` | 15.788 | 14.401 | 1.10× | 96 → 96 |
| `backward/key` | 26.388 | 24.047 | 1.10× | 96 → 96 |
| `backward/filler2` | 59.421 | 53.260 | 1.12× | 96 → 96 |
| `backward/long-string` | 50.553 | 35.720 | 1.42× | 96 → 96 |

Исходные CSV: [backward-find-results](backward-find-results/).

## Проверка

80 тестов проходят. Новая проверка содержит 640 комбинаций длинных строк с кавычками, скобками, `#` и различной длиной последовательностей слешей; проверяются границы и строк, и контейнеров. Существующие случайные проверки в обоих направлениях и сверка результатов правок через Jackson также проходят.

Стратегия Jackson и `KeysScenario` не изменены.

```sh
mvn test dependency:build-classpath -Dmdep.outputFile=target/benchmark-classpath.txt
java -Xms512m -Xmx512m \
  -cp "target/test-classes:target/classes:$(cat target/benchmark-classpath.txt)" \
  ru.sber.lazyjson.BackwardFindBenchmark
```

Для сравнения версий используйте один и тот же `BackwardFindBenchmark` с помощником `JsonBytesBenchmark`, одинаковые JVM и параметры памяти. Повторите команду `java` три раза в отдельных JVM.
