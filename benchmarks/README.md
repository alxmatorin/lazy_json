# Проверка lazyjson — 10 сентября 2026

Последние замеры: [индекс корня и пакетные правки на JSON с 10 корневыми полями](ROOT_AND_EDITS.md). В текущем `LazyLoopMain` запускается только LazyJson; Jackson-стратегия исключена из списка запускаемых стратегий.

Следующий этап: [ускорение прямого поиска `$key1.key2` на KeysScenario](TAIL_FIND.md).

Проверялись поиск, обратный обход, wildcard, вставки и пакетные правки. Ускорения относятся к конкретным операциям; полного ускорения сканирования любого JSON эти изменения не дают.

## Исправления корректности

- Пакет `$a = 1`, `$a.b = 2` при отсутствующем `a` молча терял вторую правку. Конфликт родителя и потомка теперь отвергается до обхода документа, независимо от порядка правок.
- Пути, требующие объект и массив в одном узле, частично игнорировались. Теперь такие пакеты отвергаются.
- Вставки одного ключа через wildcard и конкретный индекс создавали дублирующиеся поля. Теперь это конфликт; вставки разных ключей в один объект остаются допустимыми.
- Экранированные одиночные Unicode-суррогаты превращались в `?`, что приводило к совпадению разных ключей. Декодирование сохраняет UTF-16 символы, а вставка корректно экранирует их.
- Обратный сканер мог принять исчерпание входа за найденную открывающую скобку в позиции 0. Разделены кодирование результата и сигнал продолжения поиска.
- Отсутствующее значение больше не возвращается как пустой `Slice`.
- `findAll` с обратным обходом сохраняет порядок документа и при повторяющихся корневых ключах.

Документ и вставляемые значения должны быть корректным JSON в UTF-8. Библиотека пропускает ненужные участки и может завершить поиск раньше конца документа; полной валидации JSON она не выполняет. Это явно указано в `JsonBytes`.

## Изменения производительности

- Поиск внутри элемента массива сразу входит в нужный элемент. Раньше перед этим полностью сканировалось его содержимое.
- При обратном обходе найденное конечное значение возвращается по уже известным границам, без повторного прохода вперёд.
- `find` хранит один результат без `ArrayList`; чтение не создаёт массивы учёта отсутствующих ключей.
- `put` и одноэлементный `apply` переиспользуют дерево скомпилированного пути. Значения правок в кэш не попадают.
- Одиночная замена собирается тремя копированиями без сортировки и временных коллекций. Коллекции для дополнительных замен и вставок создаются по необходимости.
- Подготовка пакета не использует Stream и проходит по входному списку итератором, в том числе для `LinkedList`.

## Замеры

macOS arm64, Temurin JDK 21.0.7, `-Xms512m -Xmx512m`. Сравниваются сохранённый исходный `lazyjson` и изменённый `lazyjson`, одним и тем же `JsonBytesBenchmark`. Подготовка документов и значений вынесена из измеряемых циклов.

Для каждой версии запущены три отдельных JVM. В каждой операции — три окна прогрева по 200 мс и пять измерительных окон по 200 мс. В таблице медиана трёх медиан; память измерена через `ThreadMXBean.getThreadAllocatedBytes`. Проверка времени выполняется раз в 256 операций, результат используется в контрольной сумме. Это локальный сравнительный стенд, не JMH и не оценка задержек под конкурентной нагрузкой. Разницу в несколько процентов не следует трактовать как устойчивое ускорение.

Основной большой документ содержит строку на 500 000 байт. `structured` содержит 2001 объект с вложенными объектами, массивами, числами, строками и boolean. В `index-head` поле `id` находится в начале единственного большого элемента массива. Wildcard читает 1001 объект; малый документ для правок — несколько десятков байт.

Полное сканирование и копирование большого документа остались примерно на прежнем уровне. Малый пакет из двух правок в этих запусках стал примерно на 7% медленнее при меньшем выделении памяти; устойчивого ускорения пакетного режима не заявляем, проверки конфликтов сохранены.

Исходные результаты: [results](results/). CSV содержит имя операции, нс/операцию и выделенные байты/операцию; последняя строка — контрольная сумма.

Чтобы повторить замеры текущей версии с выбранным JDK 21:

```sh
mvn test
java -Xms512m -Xmx512m -cp target/test-classes:target/classes ru.sber.lazyjson.JsonBytesBenchmark
```

Повторить команду `java` три раза в отдельных JVM. Для сравнения с другой версией нужно использовать тот же исходник `JsonBytesBenchmark`, те же JVM и параметры памяти.

## Проверка

76 тестов: исходные проверки, регрессионные случаи, 300 случайных сценариев чтения и пакетных правок со сверкой через Jackson, 8000 вариантов расположения случайных JSON-значений и 640 вариантов экранирования на границах блоков с проверкой обоих направлений сканирования.

`JacksonStrategy` и `LazyStrategy` сохранены в исходном виде. Jackson эмулирует полный цикл `byte[] → Map → изменение → byte[]`; для поискового сценария изменением остаётся добавление `touched`. Сравнение двух стратегий поэтому измеряет именно эту модель нагрузки. В `LazyLoopMain` исправлен учёт последнего неполного окна и числа итераций меньше 1000.
